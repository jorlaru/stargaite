# Phase 6 design

Status: the design phase 6 is built from. It builds on the code at `03ffd6a` and on `docs/design/phase-1.md` to `docs/design/phase-5.md` (cited as "phase-N §M"). Its input is one manual deployment on a clean Debian 13 machine (2026-11-17), by a person following the README alone, with no assistant and no knowledge of the code, cited as "the manual test". It stopped at the first step of "Deploy with Docker"; its findings are stated in §1 in their own words. Rule ids (PAR, OPS, SEC, PUB, AC, PRI, USE, RSN, R) are the kick-off's and binding; where one must change, §12 gives the exact wording and the design assumes it. Code and documents are cited as `path:line` of `03ffd6a`. Compose behaviour marked **measured** was checked with `docker compose config` (Compose v5.7.1) during the review of this design; nothing else was run. Every step is **not tested live** until the live check of §7.

## 1. Scope and outcome

The proxy works; reaching it does not. The manual test found three frictions:

| Finding | What happened | Root cause |
|---|---|---|
| F1 | The first code block of the README ("Quick start", `README.md:94-115`) was pasted on an empty machine: `go`, `curl` and `./stargaite` do not exist | The first block a reader meets is the developer's path (a clone, Go 1.27.4, the mock provider); its requirements are in the prose above it, and the deployment path is named only in a parenthesis (`README.md:90-91`) |
| F2 | Step 1 of "Deploy with Docker" opened `vi` (`"${EDITOR:-vi}" .env`, `README.md:158`); the reader could not leave it, the arrow keys wrote lines of `D`, and the example key line was saved with an extra character | A text editor is the interface for giving a credential, and the default editor of a clean machine is the hardest one |
| F3 | The reader asked for "a more guided, easy console" | The README asks for Docker, an editor and the CLI's vocabulary before anything answers; nothing checks the machine or says what is missing |

Preparing this design found two more, which an assistant would hit at once:

| Finding | Evidence | Consequence |
|---|---|---|
| F4 | `compose.yaml:6` builds with no `VERSION` argument, so every Compose deployment reports `dev` (`Dockerfile:2`) | No upgrade can be detected or checked |
| F5 | The restore recipe (`README.md:795-804`) moves files in `data/` with `install`; with Compose the store is in a named volume and the image has no shell (`Dockerfile:10-17`) | A Compose deployment has no restore it can run, though OPS-7 asks for a tested one |

This phase adds one guided entry point, closes F4 and F5 at their root, and rewrites the README around the assistant.

**The rule this design adds:**

> **A person reaches a first answer by answering questions, not by editing files.** `setup.sh`, at the root of the repository, is the only program in the project that asks. It checks the machine, writes `.env` and `compose.override.yaml`, starts the container, and changes the proxy's configuration only through the CLI that already exists, which validates every change and names what to fix. Every question has a flag; with every answer given, or without a terminal, it never asks.

At the end of phase 6:

- `./setup.sh` on a clean Linux machine with Docker checks what is missing and says how to install it, builds and starts the container, and walks the reader from a provider to a key and a first answer; every credential is typed hidden, and none is in a file the reader edits (C54).
- Run again, it adds a provider, an alias, a key, a budget or telemetry to a running installation, saying first when a change briefly restarts the container (C55).
- It publishes the data plane beyond loopback only with TLS, as SEC-6 asks: the reader's certificate or a self-signed one it generates (C56).
- It tells the reader, when asked, whether the clone's remote has a newer version, and upgrades keeping the previous image and taking a backup just before the new version starts, refusing what it cannot do safely (C57).
- `stargaite backup -` writes the copy to standard output and `stargaite restore` puts a copy back while `serve` is stopped, for the binary and the container alike (C57).
- The README starts with `./setup.sh`; the Go quick start stays, renamed for developers; the manual Docker path writes `.env` without an editor (C58).

**Paid calls.** The assistant makes two kinds of paid call, each only after printing how many: `targets verify --max-output-tokens 256` (one call per level the target declares, one more at `none` when it can disable, else one: `README.md:710-713`) and one test chat completion with `max_tokens: 256`. A target that is already verified is not verified again unless the reader asks. It never retries a paid call, never loops over one, and stops at the first failure with the provider's message. Interrupting the script does not cancel a verify already sent: the server bounds it to the number of calls times the provider's `total_ms` plus 5 s (`internal/cli/client.go:50-53`, `internal/admin/verify.go:55`); the script prints that bound before it starts. Listing a provider's models is a free `GET`. The tests run against the mock provider only.

|---|---|---|
| OPS-2, AC-41, OPS-11, AC-54 (K19 to K22, K24) | No `stargaite` command asks; `setup.sh` asks only at a terminal and only for an answer no flag gave; a missing answer without a terminal exits `2` naming the flag | `TestSetupNoTTY`, `TestSetupPrompts` |

## 2. Decisions

| Decision | Choice | Reason | Discarded |
|---|---|---|---|
| What the assistant is | One bash script, `setup.sh`, at the root | With Docker the binary lives in the container; writing `.env`, `compose.override.yaml` and running Compose are host tasks the container cannot do without the Docker socket, which gives it the host | A `stargaite setup` command in Go plus a host script (two pieces, the questions split between them); mounting the Docker socket |
| How it configures the proxy | Only through `docker compose exec -T stargaite /stargaite <command> --json`, the answers read with `jq` | The CLI validates every change and names what to fix (OPS-5); the answers are nested JSON (`internal/admin/providers.go:48-51`, `internal/config/service.go:78-84`) and bash has no parser | Writing YAML for `apply` (a second spelling of the configuration); parsing JSON with `sed` |
| When it asks | Only when standard input and standard output are both a terminal and a needed answer was not given as a flag | OPS-2's guarantee for scripts, agents and CI: the same run with flags never waits | Asking whenever an answer is missing (a pipeline would hang) |
| Shape | Subcommands `install`, `provider`, `alias`, `key`, `budget`, `telemetry`, `remote`, `upgrade`, `status`, `help`; with none at a terminal, `install` when the Compose project has no container and a menu of the others when it has one | One function per action, the guided path and the flags path calling the same function; "an installation" is one fact Compose already knows (`docker compose ps -a -q`) | One linear wizard (cannot add a second provider) |
| Resuming | Every step reads what exists and reuses it: a provider, a target or an alias that exists is kept and named, never recreated | A run interrupted at any step continues by running it again | Failing on the existing name and sending the reader to the raw CLI (F3 again) |

## 3. The assistant's contract

These hold for every subcommand and the tests of §7 check them; K21 makes their core binding as OPS-11 (rules 1 to 6 and 8; rule 7 is how the design meets them).

1. **It asks only at a terminal** (`[ -t 0 ] && [ -t 1 ]`) and only for an answer no flag gave. Otherwise an answer with a default takes it (port, alias, key name, rate, output cap, effort), and a missing answer without one exits `2` with `missing --<flag>: <what it is>`. Every question shows its default in brackets; Enter takes it.
2. **It says what it will change before changing it.** A change that replaces something (a variable in `.env`, the override, the running container) or briefly interrupts traffic (recreating the container to read a new credential, which also resets in-memory rate-limit windows; turning on TLS, after which local clients need `https://`) states that, then asks for confirmation at a terminal or needs `--yes` without one.
3. **Exit codes are OPS-2's**: `0` done, `1` a failure it explains, `2` wrong usage or a missing answer.
4. **No secret leaves `.env`.** A provider or telemetry credential is read hidden, written only to `.env`, never echoed, never in the argv of an external command: a `curl` that needs a credential or the new client key reads its header from standard input (`printf '%s' ... | curl -K -`). A client key is printed once, inside a frame, and written nowhere.
5. **It never uses `sudo`, never installs packages, never edits `compose.yaml`, never removes a volume, and never runs `git reset`, `git checkout` or a merge that is not a fast-forward.**
6. **Every wait is bounded**: readiness 120 s, `git fetch` 20 s, each HTTP call 30 s, each CLI call the CLI's own timeout (90 s; a verify or a backup by the server's deadline, `internal/cli/client.go:50-53`), a build 20 minutes. On a timeout it prints the last 30 log lines and exits `1`.
7. **It holds no state of its own** beyond the `# setup:` lines of the override. What exists is read each time from `.env`, the override and the CLI (`providers list`, `targets list`, `models list`, `keys list`, `telemetry status`, `version`, all `--json`). The `# setup:` lines also say whether TLS is on, so every readiness check, CLI call and test call after `remote` uses `https://` and the admin variables of §2.
8. **Paid calls** are those of the "Paid calls" paragraph of §1, announced with their count and bound, never retried.

## 4. The flows

### C54. Install: from a clean machine to a first answer

1. **Check the machine.** bash 4.4; run from the clone (`compose.yaml` beside it); the root rule; Docker CLI, daemon reachable (`docker info`), permission (a "permission denied" says: run as root, or join the `docker` group, which is equivalent to root); Compose 2.24.4 or later; curl; jq; the host port free on `127.0.0.1` (bash `/dev/tcp`): `4000`, or `--port`, kept as `STARGAITE_PORT='<n>'` in `.env`; a taken port is reported with `--port` as the way out. Everything missing is listed at once with its install link, then exit `1`.
2. **Start.** Create `.env` (mode `0600`) if missing; export `STARGAITE_VERSION` (`dev` without git); `docker compose up -d --build`, its output shown; wait for `/health/ready`.
3. **Provider.** A numbered list from `providers presets --json` (name, whether it is tested, whether it needs a URL), plus "another OpenAI- or Anthropic-compatible service" (name, protocol, URL, credential variable). A preset without a URL asks for one; a local URL gets the local-provider handling. `providers add` runs first, so the CLI checks the variable name (SEC-5) and the URL (SEC-4) before any secret is typed; then, when the provider has a credential variable, the credential is read hidden and written to `.env`, the container is recreated (announced, rule 2), and `providers show --json` must say `credential: resolved` (or `none` for a provider without one).
4. **Model.** The provider's model list, filtered, or a typed id.
5. **Target.** `targets add <provider>/<model> --kind chat`, reused when it exists.
6. **Check it.** Unless the target is already verified and the reader does not ask again: the count and bound, then `targets verify --max-output-tokens 256`; on failure the provider's message and exit `1`, before any alias exists.
7. **Alias.** A name (default `main`); toward an `anthropic` target, `--max-output-tokens` (default 8192), which the CLI requires (`README.md:199`); an optional default effort; `models add`, or the existing alias named and kept.
8. **Key.** A name (default `my-app`), `--rpm-limit` (default 60); `keys create --json`; the key printed once. A key with that name that exists is kept, its secret cannot be shown again, so the script asks for another name or skips step 9 and says so.
9. **First answer.** One chat completion through the data plane with the new key and `max_tokens: 256`; it prints the answer, the `finish_reason`, the time and `x-stargaite-target`; then the base URL, the alias, a client example with a placeholder for the key, and how to run the assistant again.

C54 also carries the base of every later step: the question and flag helpers, the `.env` writer, the override writer, the CLI wrapper, the readiness wait, the `compose.yaml` build argument, the ignore files, the amendments K19 to K22 and K26.

### C55. Run again

- **provider**, **alias**, **key**: steps 3 to 9 of C54 on a running installation, each alone, reusing what exists.
- **budget**: on a key, an alias or the instance: the script applies `--budget limit_usd=<n>,reset_interval=daily|monthly|never`; when the CLI refuses it with `unpriced_under_budget` findings (USE-12, `internal/config/validate.go:453`), it asks for the prices of exactly the targets named (USD per million input and output tokens, `as_of` today), sets them with `targets set --pricing`, and applies the budget once more. A target priced by its provider's `cost_report`, or a `subscription` or `none` provider, is never asked about.
- **telemetry**: Langfuse (the endpoint asked, `https://<host>/api/public/otel`, `--preset langfuse`, its two keys read hidden) or any OTLP endpoint (an optional header credential read hidden into `.env`); a private or plain-HTTP endpoint is offered `--allow-private-network`, a local one gets the local-provider handling; the container is recreated when `.env` changed (announced); then `telemetry set` and `telemetry test`, whose line is printed as it comes.
- **status**: what runs (version, `docker compose ps`), providers with their credential state, targets with `verified_at`, aliases, keys (names, never secrets), telemetry, and the published addresses; `status --check` also fetches and says whether an upgrade is available.

### C56. Remote access, always with TLS

The reader gives the addresses to publish on (the host's addresses are listed from `hostname -I` when it exists), and picks:

1. **Your certificate.** Paths to a certificate chain and its key, the name on it to reach the admin listener, and, when the reader says it is from a private CA, the CA's certificate; all copied into `tls/` with the owner rule of §2. The override mounts `tls/` read-only, replaces `--behind-tls-proxy` with `--tls-cert` and `--tls-key`, publishes the host port (`STARGAITE_PORT`, default `4000`) on each address with `ports: !override`, and maps the name to `127.0.0.1` with `extra_hosts`. The CLI calls pass `STARGAITE_ADMIN_URL=https://<name>:4001`, plus `SSL_CERT_FILE=/tls/<CA file>` for a private CA. An address beyond loopback without a certificate is refused.
2. **A self-signed certificate.** `openssl` (checked for this choice only) makes a leaf with `basicConstraints=CA:FALSE` and `extendedKeyUsage=serverAuth`, valid for `localhost`, `127.0.0.1`, the host's name and each chosen address, for 825 days; the rest as choice 1 with `localhost` as the name and `SSL_CERT_FILE` set. The script prints how each kind of client trusts that one certificate without replacing its bundle (`curl --cacert`, Python's `verify=<file>`, `NODE_EXTRA_CA_CERTS`, the system trust store).

Both end with the firewall warning, the certificate's expiry (when `openssl` is present), the new CLI alias, and an HTTPS readiness check on each address. `serve` reads the certificate once at start (`cmd/stargaite/serve.go:126-131`): renewing means running `remote` again, which recreates the container.

### C57. Backup, restore and upgrade

**In Go.** `stargaite backup -` writes the copy the server streams to standard output, refused when standard output is a terminal; checks the byte count against the announced length; writes its summary (`-: <n> bytes`, or `{"path":"-","bytes":n}` under `--json`) and any error to standard error; and exits `1` on a mismatch. `stargaite restore <file|-> --yes` follows the row of §2: lock, checks before anything moves (integrity, foreign keys, not WAL, `user_version` at or below the binary's), temporary copy, the current files into an emptied `replaced/`, rename, and a summary of what it moved; without `--yes` it exits `2`; a terminal on standard input with `-` exits `2`. `serve` then runs any newer migration at start, as today. The README's restore section uses it for both deployments.

**In the script, `upgrade`:**

1. **Detect.** Refuse a detached HEAD, a branch with no upstream, local changes to tracked files, or a branch that cannot fast-forward, naming which (exit `1`). Fetch (bounded). Already up to date: say so and exit `0`, with no backup. Otherwise show at most 20 commits between `HEAD` and the upstream; say whether any migration changed (`internal/store/migrations`), and that migrations are one-way; compare the running version with `git describe` (a `dev` build says the running version is unknown); check that the running CLI has `backup -` (§2, a build from before this phase).
2. **Keep the previous image.** `docker tag <running container's image id> <image>-previous`.
3. **Update and build.** `git merge --ff-only`; export the new `STARGAITE_VERSION`; `docker compose build`. A build failure says: still running `<old version>`, store unchanged, and how to return the clone (`git reset --hard <old revision>`, which the script prints and does not run).
4. **Back up.** `docker compose exec -T stargaite /stargaite backup - > backups/<old version>-<UTC time>.db` (umask `077`), the file's size compared with the byte count the CLI reports on standard error; a failure removes the file and stops, with the old container still running.
5. **Start and check.** `docker compose up -d --no-build`; readiness; the post-upgrade check of §2; on failure the exact restore of §2 with the backup's path, and exit `1`.

## 9. Risks

| Risk | Sign | Retired by |
|---|---|---|
| A credential leaks through argv, the screen, a log or the build context | The value in `ps`, the terminal, `docker compose logs` or an image layer | §2 credentials and local files; §3 rule 4; `TestSetupSecrets` with its leaking fixture |
| A pipeline, an agent or a git remote makes the script wait | A CI job waiting for input | §3 rule 1; the fetch's environment and watchdog; `TestSetupNoTTY` |
| An upgrade replaces `setup.sh` while it runs | A syntax error after the merge | `main "$@"; exit` (§2) and the upgrade row of `make setup-test` |
| An upgrade with a one-way migration fails | The new binary does not start | The previous image and a fresh backup before the start, the exact restore printed and tested (C57) |
| A second feature of the override erases the first | TLS gone after adding a local provider | The override regenerated from its `# setup:` lines; `TestSetupOverride` |
| The generated certificate becomes a signing key | A leaf accepted as a CA | `CA:FALSE`, `serverAuth` (C56) |
| A private CA becomes trusted for provider connections | `serve` accepts a provider certificate signed by it | `SSL_CERT_FILE` per CLI call, never in the service environment (§2) |
| The script drifts from the CLI | A flag or JSON field renamed in Go breaks the script | The end-to-end test against the real image, in CI |
| The assistant grows into a second configuration layer | Rules duplicated in shell | §2: only the CLI changes the configuration; the budget flow reacts to the CLI's findings instead of restating USE-12 |
